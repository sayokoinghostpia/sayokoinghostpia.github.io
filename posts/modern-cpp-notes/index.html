我常用的现代 C++ 小技巧

RAII、智能指针、optional、string_view、span、constexpr 与结构化绑定的实践笔记。

C++

目录

这里记几个我在写小项目时反复用到的 C++ 特性。不是语言规范大全， 更多是「用了之后代码变短、出错变少」的习惯。

RAII 与所有权

C++ 最舒服的地方是资源可以跟对象的生命周期绑定。堆内存用 std::unique_ptr 管，需要共享时再考虑 std::shared_ptr。对于 COM 这类需要手动 Release 的对象，可以写一个很小的删除器： 

#include <memory>

struct ComDeleter
{
    template <typename T>
    void operator()(T* p) const
    {
        if (p) p->Release();
    }
};

using TexturePtr = std::unique_ptr<ID3D11Texture2D, ComDeleter>;
TexturePtr texture(rawTexture);

这样即使中途 return 或抛异常，资源也会被释放。比起到处手写 Release()，出错的概率小很多。

optional、string_view 与 span

这三个类型分别解决「可能没有值」「只读字符串视图」「连续内存视图」。 它们都不拥有数据，适合放在函数参数里，避免不必要的拷贝： 

std::optional<std::string> findName(int id);
std::string_view name = "hw3d";
std::span<const float> vertices(buffer);

用 optional 比返回空指针或特殊值更清楚；用 string_view 接收字符串参数时，记得调用方要保证数据活得足够久。 span 也是同理，它不会帮你管理内存。

constexpr 与结构化绑定

能在编译期算出来的东西就尽量交给编译器；能一次拆开的返回值就用结构化绑定： 

constexpr int kMaxLights = 8;

auto [width, height] = windowSize();
if (width <= 0 || height <= 0)
{
    return false;
}

constexpr 让常量真正成为常量，也方便写数组大小和编译期检查； 结构化绑定则让返回多个值的函数用起来更自然。

一点小习惯

  • 能用 const 就用 const，包括成员函数和局部变量。
  • 遍历容器时优先用 const auto&，避免隐式拷贝。
  • 接口里用 std::string_view 或 std::span，存储里再持有拥有型对象。
  • 不要为了「现代」而现代；读得懂、能维护比炫技重要。
