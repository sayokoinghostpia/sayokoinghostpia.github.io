用 Vite 和 GitHub Pages 搭一个静态博客

记录这个站点的结构、Vite 构建、.nojekyll 和发布流程。

Web 建站

目录

这个站点没有服务器，也没有数据库。它只是一组 HTML、CSS、JavaScript 和图片，构建好后放到 GitHub Pages 上。下面记录一下这套结构是怎么工作的。

为什么是静态站点

个人博客的内容更新频率不高，也不需要用户登录、评论或实时数据。 静态站点把这些复杂度全部去掉：浏览器直接拿到文件，打开就能看。 托管成本几乎为零，速度也快，而且所有内容都在 Git 仓库里， 迁移和备份都很直接。

项目结构

源码在 release_source 目录。根目录和 posts/ 下是手写的 HTML 页面；src/styles 放 CSS， src/main.js 放交互脚本；public/ 放图标、RSS、sitemap 和 .nojekyll 这类不需要构建处理的文件。

页面里的资源路径都以 / 开头，例如 /src/styles/main.css 和 /posts/hello-world/。 这样无论页面在几层目录下，路径都不会错。

Vite 做了什么

开发时，Vite 提供一个本地服务器，修改文件后浏览器自动刷新； 构建时，它把 CSS 和 JavaScript 打包、压缩，并给文件名加上哈希， 最后输出到 dist/。常用命令只有几个： 

npm install
npm run dev
npm run build
npm run preview

dev 用于日常修改，build 生成最终产物， preview 用本地服务器模拟线上环境。注意不要用 file:// 直接打开 dist/index.html： 构建后的资源路径是 /assets/...，在文件协议下会找不到。

发布到 GitHub Pages

发布仓库是 sayokoinghostpia.github.io，它对应 https://sayokoinghostpia.github.io/。 GitHub Pages 被配置为从 main 分支根目录发布。每次构建后， 把 dist/ 里的内容复制到仓库根目录，提交并推送， GitHub 就会自动重新构建站点。

复制时要注意保留 .git/、README.md 和 .gitignore，不要为了「干净」把整个目录删掉。 更新时只需要清理旧的 assets/、posts/ 等构建产物。

一个容易被忽略的文件：.nojekyll

GitHub Pages 默认会用 Jekyll 处理仓库内容。对于纯静态站点， 这层处理没有必要，还可能带来意外。根目录放一个空的 .nojekyll 文件，就能让 GitHub 跳过 Jekyll， 直接按原样提供文件。这个文件名字以点开头，Windows 资源管理器默认不显示， 用终端或编辑器才能看到。

这次学到的事

  • 路径要从站点根开始想，而不是从当前文件开始想。
  • 源码和构建产物要分开，dist/ 永远不手改。
  • 部署前先在 preview 里把每个链接点一遍。
  • Git 仓库里的 .git/ 是历史，不要覆盖或删除。

这套结构不复杂，但足够支撑一个长期维护的个人站点。 以后内容多了，再考虑把 Markdown 自动转换成 HTML，或者加一个自动生成 RSS 的脚本。
